# Track B Implementation Plan

**Goal:** Answer the six specified stakeholder questions from an auditable local ledger.
**Architecture:** CSV normalization and deterministic deduplication populate in-memory SQLite; a bounded question router chooses parameterized, read-only SQL. Independent fixtures test business rules and refusal.
**Tech Stack:** Python 3 standard library, SQLite.
**Spec:** `specs/track-b-spec.md`.

## Tasks
1. Write fixture-driven tests, observe failure, implement ingestion and account snapshots; verify FX, duplicate precedence, dates, active MRR, and churn.
2. Implement the six bounded query templates and explicit refusal; verify SQL, parameters, fixture results, and a marked expected failure.
3. Document commands, quality disclosures, diagram, AI instructions and real prompt history; run against the actual data and a clean checkout.
4. Request the specified independent Claude review if possible, evaluate its findings, rerun checks, and record evidence.

Review focus: conflicting duplicate invoices, ambiguous dates, missing invalid data, repeated account invoices, and unsupported/adversarial questions.
